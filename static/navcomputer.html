Navigation Computer 挂载点输入台 通过本机 Kepler 服务器转发（/api/nav/*）

所有请求发往本机 Kepler 服务器（），由服务器转发到 Navigation Computer，避免浏览器跨域限制。转发时自动附加路径前缀 /api/navigation/v1 与 Authorization: Bearer 头。
环境变量 KEPLER_NAVCOMPUTER_URL / KEPLER_NAVCOMPUTER_TOKEN 可设默认基地址与令牌。

0 · 连接配置 / 健康检查 GET /health · GET /status

1 · 预准备 CT 查询（缓存优先） POST /prepared-ct-lookups

查询是否已有对应的 Prepared CT。命中返回 Prepared CT ID；未命中返回 miss。

2 · 上传并准备 CT POST /prepared-cts

缓存未命中时上传 ZIP。流程：Stream → validate → prepare → atomic publish，返回 201 + Prepared CT ID。

3 · 设置配准（Registration） POST /setup-registrations

JSON + F1 MHA + F2 MHA。返回 202 + operation + evidence IDs；后续通过回调推送 Validate → register → compose → accept 事件（见第 4 块）。

4 · 实时导航 / 目标观察 POST /setup-registrations/{id}

5 · 获取DRR GET /api/nav/setup-registrations/{id}/drr-previews/{frame}

6 · 查询导航会话 GET /navigation-sessions/{id}

读取 Navigation Computer 上导航会话的当前状态。

7 · 注册事件回调 / 实时状态 PUT /callbacks/…/events/{seq} · PUT /callbacks/…/live-state

Navigation Computer 会把配准事件推送到本机这两个挂载点（有序、幂等、204 确认）。 这里可手动模拟推送，验证接收端是否工作。
